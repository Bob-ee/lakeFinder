# web — Michigan seaplane lake map (PWA client)

Vite + vanilla TypeScript + MapLibre GL + pmtiles. No UI framework.

Phase 1 of `docs/design.md`: static map, verdict outlines, tap for the detail sheet,
typeahead search, `?lake=<id>`. Location, wind, offline packs and saved lakes are phases
2 to 4; their module folders exist with placeholders so nothing has to move later.

## Run it

```bash
cd web
npm install
npm run dev          # http://localhost:5173
```

`/data/*` is served by a Vite plugin (`dataRangeServer` in `vite.config.ts`) with HTTP
byte-range support, because pmtiles fetches every tile with a `Range` header. It serves:

- `../data/out/` when `../data/out/pack.json` exists (real pipeline output), otherwise
- `web/dev-fixtures/` (the checked-in fake dataset).

`npm run preview` serves the production build through the same middleware. Production is
Caddy, which does ranges natively. Set `SEAPLANE_DATA_DIR` to force a directory, which is
useful when the pipeline output is mid-rebuild:

```bash
SEAPLANE_DATA_DIR=dev-fixtures npm run dev
```

Other scripts:

| script | what |
|---|---|
| `npm run build` | production bundle into `web/dist` |
| `npm run typecheck` | `tsc --noEmit`, strict |
| `npm run fixtures` | regenerate `web/dev-fixtures` (needs `tippecanoe` on PATH) |

## Dev fixtures

`scripts/make-dev-fixtures.mjs` writes ten plausible Oakland County lakes with six
restrictions, covering all four verdicts plus an unnamed polygon. It emits `index.json`,
`restrictions.json`, `rules.json`, `pack.json` (committed) and `lakes.pmtiles`,
`usable_water.pmtiles`, `overlays.pmtiles` (gitignored, regenerate with the script).

`rules.json` is copied from `../rules/rules.json` when that exists; otherwise the script
falls back to a built-in rule set that matches the contract.

`basemap.pmtiles` is a one-off Protomaps extract and is not regenerated by the script:

```bash
cd web/dev-fixtures
# pick the newest build name from https://build.protomaps.com/
pmtiles extract https://build.protomaps.com/20260915.pmtiles basemap.pmtiles \
  --bbox=-83.7,42.4,-83.0,42.9 --maxzoom=14
```

That is about 25 MB for the Oakland County box. Every `.pmtiles` under `dev-fixtures/` is
gitignored; the app degrades gracefully when any of them is missing (HEAD 404 leaves the
layer out with a console warning).

## Shared rules engine

The client re-runs the shared engine so a rules change ships without a tile rebuild.
`vite.config.ts` aliases `@rules` to `../rules` and exposes a `virtual:rules-engine`
module that re-exports `rules/engine/index.js` when it exists and nulls when it does not.
With no engine the app falls back to the prebaked `verdict` in `index.json` and says so in
Settings and in the sheet.

`src/search/normalize.ts` is a local copy of the contract's name normalization and prefers
the engine's `normalizeName` at runtime when it is available.

## Bundle and the MapLibre worker

`npm run build` produces about 108 kB of app code (32 kB gzipped) plus MapLibre's own dist
files, which are deliberately left unbundled:

```
dist/assets/index-*.js               app
dist/vendor/maplibre/maplibre-gl.mjs        main thread
dist/vendor/maplibre/maplibre-gl-shared.mjs shared by both threads
dist/vendor/maplibre/maplibre-gl-worker.mjs tile parsing worker
```

MapLibre 6 ships as three sibling ESM files and works out its worker URL at runtime from
`import.meta.url`. Bundling it into one chunk points that URL at a file that does not
exist: the worker never starts, every tile sits in "loading", and the map renders blank
with no error in the console. So `vite.config.ts` marks `maplibre-gl` external, rewrites
the import to `/vendor/maplibre/maplibre-gl.mjs`, and copies the three files into the
output (`maplibreAssets`). Dev does the same thing with `optimizeDeps.exclude`. Keeping
`maplibre-gl-shared.mjs` a separate file also means the worker gets it from the HTTP cache
instead of downloading a second copy.

## Theme, storage, offline

- Dark/light follows the system with a manual override in `localStorage` (every access is
  wrapped in try/catch).
- IndexedDB db `seaplane`, stores `saved`, `recent`, `wind`. Only `recent` is written in
  phase 1.
- No service worker yet. `src/sw/README.md` holds the phase 3 plan.
- Basemap glyphs and sprites come from `protomaps.github.io` while online; self-hosting
  them is part of the phase 3 offline work.
